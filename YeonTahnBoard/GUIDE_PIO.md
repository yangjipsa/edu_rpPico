<a name="1"></a>
## 1. PIO가 대체 뭔가요?

**PIO(Programmable I/O) = 핀을 대신 흔들어 주는, 아주 성실한 보조 일꾼입니다.**

### 🍳 주방 비유
- **CPU = 사장님(주방장)**: 머리가 좋아 여러 일을 하지만, 몸은 하나라 바쁩니다.
- **PIO = 알바생**: 딱 정해진 "레시피 카드"대로, **정확한 박자에 맞춰** 반복 작업만 합니다.

사장님이 "이 카드대로 계속해" 하고 카드를 건네면, 알바생은 **사장님이 딴 일을 하는 동안에도**
혼자서 그 작업을 정확한 타이밍으로 계속합니다. 이 알바생이 바로 PIO입니다.

> 즉 PIO는 **핀(GPIO) 전용 초소형 보조 프로세서**입니다.
> CPU와 따로 돌면서 핀을 아주 정밀한 타이밍으로 제어합니다.

---

<a name="2"></a>
## 2. 왜 필요한가요?

지금까지 배운 방식(`Pin.value(1)` / `value(0)` 반복)으로도 LED는 깜빡입니다.
그런데 이런 한계가 있습니다.

| 일반 방식(CPU가 직접) | 문제 |
|----------------------|------|
| `while` 로 핀을 흔든다 | 다른 코드·인터럽트 때문에 **타이밍이 미세하게 흔들림** |
| 신호 만드는 동안 | **CPU가 그 일에 묶여** 다른 일을 못 함 |
| 아주 빠른 신호 | 파이썬은 느려서 **고속 신호(수백 kHz)는 불가능** |

**예시**: 네오픽셀(WS2812/SK6812)은 **800kHz의 아주 정밀한 신호**가 필요합니다.
파이썬 `for` 문으로는 절대 못 만듭니다. → 그래서 PIO가 필요합니다.

<a name="3"></a>
## 3. 큰 그림 한 장

```
   ┌─────────┐   레시피 카드(프로그램)    ┌──────────────────┐
   │   CPU   │ ─────────────────────────▶ │  State Machine   │ ──▶ GPIO 핀
   │ (사장님) │   데이터(FIFO 큐)          │  (알바생, 자동실행) │      (실제 신호)
   └─────────┘ ◀───────────────────────── └──────────────────┘
                  결과값(FIFO 큐)

   ● 알바생(State Machine)은 몇 명?
     RP2040       : 8명  (PIO 2블록 × 4명)
     RP2350(피코2) : 12명 (PIO 3블록 × 4명)   ← 연탄보드
```

핵심: **카드를 한 번 건네면, 이후엔 CPU 없이 알바생이 알아서** 핀을 제어합니다.

<a name="4"></a>
## 4. 용어 하나씩 천천히

처음엔 이 5개만 알면 됩니다.

### ① State Machine (SM) — "알바생"
실제로 프로그램을 실행하는 일꾼. 위에서 봤듯이 8~12명이 **동시에 각자** 일할 수 있습니다.

### ② 명령어 메모리 — "레시피 카드 (아주 작음)"
PIO 블록 하나에 **명령 32줄**만 저장됩니다. 그래서 PIO 프로그램은 **아주 짧게** 짜야 해요.
"복잡한 판단은 CPU가, 정확한 타이밍만 PIO가" 가 기본 원칙입니다.

### ③ 클록(freq) — "메트로놈 박자"
알바생은 정해진 박자에 맞춰 한 동작씩 합니다. `freq=2000` 이면 **1초에 2000박자**,
즉 **한 박자 = 0.5ms**. 명령 하나는 보통 **1박자(1클록)** 에 실행됩니다.

### ④ 대기 `[n]` — "몇 박자 쉬어"
명령 뒤에 `[3]` 을 붙이면 그 명령 후 **3박자 더 쉽니다**. 정밀 타이밍의 핵심 도구입니다.
`set(pins, 1) [3]` = "핀을 1로 만들고 → 3박자 쉬어".

### ⑤ FIFO — "주문서 꽂이"
CPU와 알바생 사이의 **데이터 큐**입니다.
- CPU가 `sm.put(값)` → 꽂이에 주문서를 꽂음 → 알바생이 `pull()` 로 꺼내 씀
- 알바생이 `push()` → 결과를 꽂이에 올림 → CPU가 `sm.get()` 으로 가져감

(조금 더 나아가면 OSR/ISR "시프트 레지스터 = 비트를 한 칸씩 밀어내는 컨베이어 벨트"가
나오는데, 처음엔 몰라도 됩니다. 8번 섹션에서 살짝 봅니다.)

<a name="5"></a>
## 5. 내 첫 PIO 프로그램 (한 줄씩 해설)

연탄보드 **LED2(GP0)** 를 PIO로 깜빡여 봅니다. (LED2는 Active High: 1=켜짐)

```python
import rp2
from machine import Pin
import time

# ── ① PIO 프로그램(레시피 카드) 정의 ──────────────
@rp2.asm_pio(set_init=rp2.PIO.OUT_LOW)   # (a)
def blink():
    wrap_target()          # (b) 반복 시작점
    set(pins, 1)   [31]    # (c) 핀=1(켜짐), 그리고 31박자 쉬어
    nop()          [31]    # (d) 아무것도 안 함 + 31박자 (더 오래 켜두기)
    set(pins, 0)   [31]    # (e) 핀=0(꺼짐), 그리고 31박자 쉬어
    nop()          [31]    # (f) 아무것도 안 함 + 31박자 (더 오래 꺼두기)
    wrap()                 # (g) (b)로 되돌아가 무한 반복

# ── ② State Machine(알바생) 배정 ──────────────────
sm = rp2.StateMachine(0, blink, freq=2000, set_base=Pin(0))   # (h)

# ── ③ 시작! 이후 CPU 는 자유롭다 ──────────────────
sm.active(1)               # (i) 알바생 일 시작
try:
    n = 0
    while True:
        print("CPU 는 다른 일 하는 중:", n)   # (j) LED 는 알바생이 알아서 깜빡임
        n += 1
        time.sleep(1)
except KeyboardInterrupt:
    pass
finally:
    sm.active(0)                       # 알바생 정지
    Pin(0, Pin.OUT).value(0)          # LED 끄기
```

### 줄별 해설
- **(a) `@rp2.asm_pio(set_init=...)`** : "지금부터 아래 함수는 PIO 레시피 카드다"라는 표시.
  `set_init=rp2.PIO.OUT_LOW` = set 명령이 다룰 핀을 **출력으로, 처음엔 0(LOW)** 으로 시작.
- **(b) `wrap_target()` / (g) `wrap()`** : 이 둘 사이를 **무한 반복**합니다. (하드웨어 반복이라 빠름)
- **(c) `set(pins, 1)`** : set 대상 핀을 **1(켜짐)** 로. 뒤의 `[31]` 은 "31박자 쉬어".
- **(d) `nop()`** : "아무 것도 안 하기". `[31]` 로 켜진 시간을 더 늘립니다.
- **(e)(f)** : 반대로 **끄고**, 꺼진 시간을 늘립니다.
- **(h) `StateMachine(0, blink, freq=2000, set_base=Pin(0))`** :
  - `0` = 0번 알바생 사용
  - `blink` = 위에서 만든 카드
  - `freq=2000` = 박자 속도(1초 2000박자)
  - `set_base=Pin(0)` = set이 다룰 핀을 **GP0(LED2)** 로 지정
- **(i) `sm.active(1)`** : 시작! 이후 **`while` 안의 CPU 작업과 LED 깜빡임이 동시에** 돕니다.

> 🔑 핵심 체험: `set(pins,1)` 한 번 시켜두면, CPU가 `print` 하며 놀아도 **LED는 계속 깜빡**입니다.
> "핀 제어를 알바생에게 완전히 떠넘겼다"는 감각을 느끼는 게 이 예제의 목적입니다.

<a name="6"></a>
## 6. 타이밍은 어떻게 정해지나 (계산)

깜빡이는 속도 = **박자 속도(freq)** 와 **박자 수(명령+대기)** 로 정해집니다.

### 위 예제 계산
| 줄 | 박자 수 |
|----|--------|
| `set(pins,1) [31]` | 1 + 31 = 32 |
| `nop() [31]` | 32 |
| `set(pins,0) [31]` | 32 |
| `nop() [31]` | 32 |
| **한 사이클 합계** | **128 박자** |

`freq=2000` 이므로 한 박자 = 1/2000초. → **128 ÷ 2000 = 0.064초** (한 번 깜빡).
즉 **1초에 약 15번** 깜빡여서 사람 눈엔 "빠르게 떨리는" 느낌입니다.

### "천천히" 깜빡이려면?
문제: 대기값 `[n]` 은 **최대 31**, freq도 하드웨어상 **약 2000Hz 밑으로는 못 내림**.
그래서 **대기 반복(루프)** 으로 시간을 늘립니다. → 아래 7~8번 개념(레지스터·점프)을 쓴
"1초에 한 번" 버전은 함께 드리는 **`17_PIO_Blink.py`** 예제에 들어 있습니다.

<a name="7"></a>
## 7. 명령어 9개, 쉽게

PIO는 딱 **9개 명령**만 있습니다. (그래서 사고방식이 단순해요)

| 명령 | 쉽게 말하면 | 예 |
|------|------------|----|
| `set` | 핀/레지스터에 **작은 값(0~31) 넣기** | `set(pins, 1)` 핀 켜기 |
| `nop` | **아무 것도 안 하기** (대기용) | `nop() [31]` |
| `jmp` | **점프**(조건부/무조건) | `jmp(x_dec, "loop")` x 줄이며 반복 |
| `wait` | 어떤 신호가 될 때까지 **기다리기** | `wait(1, pin, 0)` |
| `in_` | 핀 값을 **읽어 담기**(ISR로) | 입력용 |
| `out` | 담아둔 비트를 **핀으로 내보내기**(OSR에서) | 시리얼 출력 |
| `push` | 읽은 값을 **CPU 쪽 큐로 올리기** | RX FIFO |
| `pull` | CPU가 준 값을 **꺼내오기** | TX FIFO |
| `mov` | 값 **복사** | `mov(x, osr)` |

> 초보 단계에선 `set`, `nop`, `jmp`, `wait` 4개면 대부분의 깜빡임·타이밍 예제를 만들 수 있습니다.
> `in/out/push/pull/mov` 는 "데이터를 비트로 주고받을 때"(네오픽셀 등) 등장합니다.

### 반복(루프) 만드는 관용구
```python
    set(x, 31)              # x = 31 (카운터)
    label("delay")         # 여기가 반복 지점
    nop() [31]             # 32박자 쉬고
    jmp(x_dec, "delay")    # x 를 1 줄이고, 0 아니면 delay 로 점프
```
이렇게 하면 `32(대기) × 32(반복) ≈ 1024박자` 를 벌 수 있습니다. 이걸 켜짐/꺼짐에 각각 넣으면
freq=2000에서도 **약 1초**에 한 번 깜빡이게 됩니다. (`17_PIO_Blink.py` 참고)

<a name="8"></a>
## 8. 데이터 주고받기 (put / get)

핀을 켜고 끄는 것 말고, **값(숫자)** 을 주고받을 수도 있습니다.

```python
sm.put(123)      # CPU → 알바생 : 주문서 꽂이(TX FIFO)에 123 넣기
값 = sm.get()    # 알바생 → CPU : 결과 꽂이(RX FIFO)에서 꺼내오기
```

알바생 안에서는:
- `pull()` : 꽂이에서 값을 꺼내 **OSR(출력 시프트 레지스터)** 에 넣음
- `out(pins, 1)` : OSR의 **비트를 한 칸씩 핀으로** 내보냄 (컨베이어 벨트처럼)
- `in_(pins, 1)` / `push()` : 반대로 핀을 읽어 CPU로 올림

이 "비트를 한 칸씩 밀어 보내는" 방식으로 네오픽셀 같은 **시리얼 신호**를 만듭니다.
지금은 "값도 주고받을 수 있구나" 정도만 알면 충분합니다.

<a name="9"></a>
## 9. 실전: 네오픽셀은 왜 PIO를 쓸까

**놀라운 사실: 여러분은 이미 PIO를 쓰고 있었습니다.** 🎉

연탄보드의 **SK6812 RGBW 4개(GP5)** 는 800kHz의 정밀 신호가 필요합니다.
그래서 MicroPython `neopixel` 라이브러리는 **내부적으로 PIO로** 그 신호를 만듭니다.
즉 `np.write()` 를 부를 때마다 알바생(PIO)이 정확한 파형을 그려주고 있던 거예요.

> 그래서 대부분의 경우 **PIO 어셈블리를 직접 짤 필요가 없습니다.**
> 누군가 이미 만들어 둔 PIO 라이브러리(`neopixel` 등)를 쓰면 되니까요.
> PIO를 직접 짜는 건 "**세상에 없는 특수 신호**"가 필요할 때입니다.

<a name="11"></a>
## 11. 언제 쓰고, 언제 안 써도 되나

**✅ PIO가 필요한 경우**
- 마이크로초(µs) 단위의 **정밀한 타이밍**이 필요
- **수백 kHz~MHz** 급 빠른 신호
- 신호를 만드는 동안 **CPU를 놀게** 하고 싶지 않음

**❌ 굳이 PIO 안 써도 되는 경우 (그냥 Pin/PWM이 쉬움)**
- 단순 LED on/off, 버튼 읽기
- 느긋한 제어(수십 ms 이상)
- 이미 라이브러리가 있는 경우(네오픽셀 등) → 라이브러리 사용

<a name="12"></a>
## 12. 초보가 자주 하는 실수

1. **프로그램이 너무 김** → 명령 32개 제한 초과. "타이밍만 PIO, 판단은 CPU".
2. **freq를 너무 낮게** → 약 2000Hz 밑은 안 됨. 느리게 하려면 **대기 루프**로.
3. **핀 지정 헷갈림** → `set` 은 `set_base`, `out` 은 `out_base`, `in_` 은 `in_base`, 사이드셋은 `sideset_base`. 명령 종류에 맞는 base를 줘야 함.
4. **`set` 에 큰 값** → `set` 의 즉시값은 **0~31**만 가능. 큰 값은 `pull`/`out` 으로.
5. **종료 처리 안 함** → `sm.active(0)` 로 멈추고 핀 정리. 안 그러면 계속 신호가 나감.
6. **이름 충돌** → 파일명을 `rp2.py`, `machine.py` 등으로 저장하면 import 깨짐.

<a name="13"></a>
## 13. 용어 사전

| 용어 | 뜻 |
|------|----|
| **PIO** | Programmable I/O. 핀 전용 프로그래머블 보조 하드웨어 |
| **State Machine(SM)** | PIO 안에서 프로그램을 실행하는 일꾼 (8~12개) |
| **클록/freq** | SM이 도는 박자 속도. 명령 1개 ≈ 1클록 |
| **`[n]` 딜레이** | 명령 뒤 n클록 추가 대기 |
| **FIFO** | CPU↔SM 데이터 큐 (TX: CPU→SM, RX: SM→CPU) |
| **OSR / ISR** | 출력/입력 시프트 레지스터(비트를 한 칸씩 이동) |
| **wrap_target / wrap** | 이 구간을 하드웨어로 무한 반복 |
| **sideset** | 명령 실행과 동시에 다른 핀을 바꾸는 고급 기능 |
